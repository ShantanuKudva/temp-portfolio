# Deployment & Content Admin Runbook

## Environment variables

| Var | Where it comes from | Notes |
| --- | --- | --- |
| `DATABASE_URL` | Neon integration (Vercel → Storage) | Pooled connection string, injected automatically. Drop `channel_binding=require` if you paste it by hand — node-postgres does not support it and the connection fails. |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob store | Injected automatically once a Blob store is connected. The store **must be public**; access mode cannot be changed after creation. |
| `PAYLOAD_SECRET` | **Set manually** | Signs login sessions. Generate with `openssl rand -hex 32`. The app will not boot without it. Changing it logs everyone out; it does not affect passwords. |

Local development uses the same three in `.env.local` (gitignored).

## Regions

Neon is in `ap-southeast-1` (Singapore) and `vercel.json` pins functions to `sin1`
so they sit beside it. Keep them together — when the database was in `us-east-1`
and the developer in India, every query cost ~208ms and the admin took minutes to
load. Measured after co-locating: ~57ms per query, `/admin` under a second.

## Free-tier limits to watch

- **Vercel Blob:** 1 GB storage, 10 GB transfer/month. Videos dominate both.
  Check Vercel → Storage → Blob → Usage as the reel library grows.
- **Neon Postgres:** 500 MB. Text content will not come close.
- Payload rejects uploads over **50 MB**; reels accept `video/mp4`, posters
  `image/*`, the rate card `application/pdf`.

## Editing content

Log in at `/admin`. The sidebar mirrors the site:

| Group | What it holds |
| --- | --- |
| **Home page** → Page copy | The neon name and the portrait's alt text. |
| **Work page** → Page copy, Reels | Headline, section intros, case study, process steps, closing CTA — and the reels themselves. |
| **About page** → Page copy | Every word on `/about`, section by section. |
| **Connect page** → Page copy, Rate card, Contact & links | Headings and marquee; the pricing tiles; email, Cal.com link, socials, rate-card PDF, response time, and the mailto starters. |
| **Account** → Users, AI access keys | Who can sign in, and which AI assistants can edit. |

Saved changes appear on the live site immediately — the four content routes
render per request rather than from a build.

### Reels

Each reel needs a **poster**; the **video is optional** so a reel can be drafted
before its clip is ready (the card shows the poster alone until then).

Upload a video **from inside the reel** — that creates a file belonging to that
reel. Do not open an existing video and replace its file: any reel pointing at it
changes too.

Uploads are stored with a random suffix, so two files both named `poster.jpg`
cannot overwrite each other.

### Rate card PDF

Upload it under **Connect page → Contact & links → Rate card PDF**. With no PDF
set, the download button hides rather than linking to a missing file. The
placeholder in the repo is generated by `scripts/make-rate-card-pdf.py`; replace
it with the real designed PDF whenever it exists.

## Editing content with Claude

The steps are also rendered inside the admin, above **Account → AI access keys**,
with the site's own address filled in.

1. In `/admin` → **Account → AI access keys** → **Create new**. A label is
   required — it is what the row is titled by. The key is shown **once**, so
   copy it before leaving the page; if it is lost, delete the key and make
   another.
2. Connect a client:

   **Claude desktop / mobile** — Settings → Connectors → Add custom connector,
   address `https://<site-url>/api/mcp`, and `Bearer <API-KEY>` where it asks
   for authentication. This is the route for a non-technical editor.

   **Claude Code** —

   ```bash
   claude mcp add --transport http portfolio https://<site-url>/api/mcp \
     --header "Authorization: Bearer <API-KEY>"
   ```

   `claude mcp list` should then show `portfolio` as Connected.

Agent calls run through the same access control and validation as the admin UI,
**including delete**, and cover every entity — reels, packages, uploads, all page
copy, site settings, and `users`. A key therefore grants account management too,
so a leaked one can create an admin account rather than merely edit content.
Treat it like a password, give each client its own, and delete keys once they are
no longer in use.

## Schema changes — read before adding or changing a field

In development Payload syncs the database automatically. That sync is
**interactive**: rename a field or change its type and it stops on a prompt like

```
Is rate_card_pdf_id column in site_settings created or renamed from another column?
```

Run `npm run seed` (or `npm run dev`) in a real terminal so you can answer it. In
a non-interactive shell it hangs forever with no output. If you are stuck, the
escape hatch is to drop the stale column yourself and let Payload create the new
one cleanly.

**Production does not auto-sync.** The deployed app expects the schema to already
match. Today that holds because the same database was migrated by local
development. Before this becomes a team workflow, generate proper migrations
(`npm run payload migrate:create`) and run them in the build — otherwise a field
added locally will break production the moment it is read.

## Resetting a password

There is no email provider wired up, so the "forgot password" link cannot send
mail. To reset an account:

- **Normal case** — the other user logs in at `/admin` → **Account → Users** →
  open the account → set a new password → Save.
- **Both accounts locked out** — create a fresh admin from the machine that has
  `.env.local`:

```bash
EMAIL=you@example.com PASSWORD='a-strong-password' NAME='Your Name' npm run create-user
```

## Restoring seed content

`npm run seed` rewrites the page copy, packages, site settings and the
placeholder rate-card PDF. It **does not** create reels — the gallery stays empty
until real ones are added — and it skips packages if any already exist, so it is
safe to re-run.

## Housekeeping

Deleting a reel does **not** delete its video or poster file. Orphans accumulate
against the Blob quota. The upload collections are hidden from the sidebar but
remain reachable for clearing them out:

- `/admin/collections/media` — posters and images
- `/admin/collections/videos` — reel videos
- `/admin/collections/documents` — the rate-card PDF
